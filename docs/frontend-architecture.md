# Frontend Architecture — Global Foundation

This is the day-1 scaffold for `resources/js/`, built before any business
features exist. It contains only cross-cutting infrastructure — no domain
modules (products, orders, CRM, etc.). Those will land later as
`resources/js/modules/<domain>/<module>/` (or similar), each with its own
`pages/components/composables/services/stores/types`, and will import from
the global folders below rather than duplicating them.

## Folder tree

```
resources/js/
├── actions/            (generated by Wayfinder — don't hand-edit)
├── assets/
│   ├── images/
│   └── fonts/
├── components/          shared, reusable UI only — never business components
│   ├── ui/               design-system primitives (button, input, badge...)
│   ├── forms/             form field wrappers, form-layout helpers
│   ├── feedback/          toasts, alerts, spinners, empty states
│   ├── layout/            app-shell pieces (header, sidebar, page container)
│   └── charts/            generic chart wrappers, no business data shapes
├── composables/          global, reusable composables (useTheme, useToast, ...)
├── constants/            cross-cutting constants (HTTP status, storage keys)
├── i18n/                 vue-i18n instance + locale message files
│   └── locales/
├── layouts/              page-level layout shells (empty until first one is needed)
├── lib/                  (existing) shadcn-vue style helpers, e.g. cn()
├── pages/                (existing) Inertia page components
├── plugins/              Vue app.use() registrations, wired into app.ts
├── routes/, wayfinder/    (generated by Wayfinder — don't hand-edit)
├── services/             infrastructure only: api, auth, upload
├── stores/               global Pinia stores only: auth, theme, locale
├── types/                global types, split by concern (not one types.ts)
├── utils/                pure, stateless helpers not tied to Vue or a domain
└── app.ts                (existing) Inertia entrypoint
```

## Why each folder exists

- **assets/** — static files that aren't run through Tailwind's `@source`
  scanning (raster images, downloadable fonts). SVGs used as components still
  live next to the component that renders them.
- **components/** — reusable, presentational UI with zero business logic.
  Split by *kind of concern* (ui/forms/feedback/layout/charts), not by
  feature, so a component here never imports from a future domain module.
  `ui/` is already excluded from ESLint (see `eslint.config.js`), matching
  the shadcn-vue convention for vendored primitives.
- **composables/** — global, reusable Composition API functions with no
  domain knowledge (`useTheme`, `useToast`, `useDebounce`, `useLocalStorage`).
  A future domain module gets its own `composables/` for business-specific
  ones (e.g. `useProductFilters`) — those never live here.
- **constants/** — cross-cutting, environment-independent values (HTTP
  status codes, localStorage key names). Business enums (order statuses,
  permissions, roles) belong inside the module that owns that concept, not
  here.
- **i18n/** — the single `vue-i18n` instance and its locale files. Feature
  modules add their own message namespaces as they're built; the instance
  itself stays global.
- **layouts/** — page-level layout shells (`AppLayout`, `AuthLayout`).
  Currently empty (no `.vue` files) since none exist yet — first real page
  that needs one creates it here.
- **plugins/** — the one place that calls `app.use(...)`. `app.ts` only
  calls `registerPlugins(app)`; adding a new global plugin later (analytics,
  error tracking, etc.) means editing `plugins/index.ts`, not `app.ts`.
- **services/** — thin, stateless wrappers around infrastructure concerns
  that outlive any one component: `api.ts` (fetch client for *external*
  APIs — Laravel itself is called via Inertia visits/forms, not this),
  `auth.ts` (client-side session helpers), `upload.ts` (generic file upload
  with progress). No `ProductService`/`OrderService` here — those belong in
  a module's own `services/`.
- **stores/** — global Pinia stores whose state is genuinely app-wide:
  `auth` (read-only view over the `auth.user` Inertia shared prop), `theme`,
  `locale`. A store belongs here only if more than one domain module needs
  it; otherwise it lives inside the module.
- **types/** — global types split by concern (`auth.ts`, `theme.ts`,
  `toast.ts`), re-exported from `types/index.ts`. Never a single growing
  `types.ts`.
- **utils/** — pure functions with no Vue reactivity and no side effects
  (formatting, parsing, math). If a helper needs `ref`/`computed`, it's a
  composable, not a util. If it needs `fetch`, it's a service.

## Naming conventions

| What | Convention | Example |
|---|---|---|
| Composable | `useX.ts`, camelCase export matching filename | `useTheme.ts` → `useTheme()` |
| Store | `x.ts`, `defineStore('x', ...)`, exported as `useXStore` | `stores/theme.ts` → `useThemeStore` |
| Service | `x.ts`, exported as `xService` object or named functions | `services/auth.ts` → `authService` |
| Type/Interface | PascalCase, no `I`/`T` prefix | `ThemePreference`, `Toast` |
| Constant | `SCREAMING_SNAKE_CASE`, one concern per file | `HTTP_STATUS`, `STORAGE_KEYS` |
| Component file | PascalCase `.vue` | `Button.vue` |
| Directory | kebab-case | `components/feedback/` |

## What's deliberately not here yet

- No `pinia`/`vue-i18n` business stores or locales beyond `en` — added when
  the first feature needs them.
- No `.vue` files under `components/*` or `layouts/` — this scaffold only
  creates the folders; components are built alongside the first page that
  needs them.
- No REST API layer — this app follows `Inertia::render()` /
  `Route::inertia()` per `CLAUDE.md`; `services/api.ts` is only for calling
  external, non-Laravel APIs.
